# ADR-003: Hand-offs are artifacts, never conversations; each agent gets the minimum it needs

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D3 (hand-offs)

## Context
What an agent sees decides what it can get wrong. Passing a full transcript to the next agent copies earlier mistakes and wastes tokens. Passing too little makes agents guess the interface. By the assignment rules, the reviewer must see only the issue, the diff and the repo at the PR head.

## Options considered
1. Full transcript of earlier stages to every agent. Maximum context, maximum bias, high cost.
2. LLM-written summaries between stages. Cheaper, but a summary can drop or invent facts and cannot be checked.
3. **Structured artifacts (JSON + rendered Markdown) validated by code, plus repository access where needed.** ← chosen

## Decision
| Agent | Receives | Deliberately does **not** receive | Why |
|---|---|---|---|
| Spec | issue title + body (wrapped as `<untrusted_issue>`), ARCHITECTURE.md §1–3 (domain terms only) | source code, tools | A1 rule: say *what*, not *how*; reading code pushes the spec toward a solution |
| Design | `spec.json`, full ARCHITECTURE.md, read-only repo tools | the raw issue (only the spec's verbatim quotes) | the spec is the contract; the raw issue may contain injected instructions |
| Implementer | `spec.json` ACs, `design.json`, tools, last check failure (tail, 4k chars) | spec/design agent conversations, reviewer prose | a fresh context per attempt keeps the context small |
| Test agent | `spec.json` ACs, `design.json`, current `git diff` | implementer's conversation and its reasons | tests derived from ACs, not from what the implementer believed |
| Reviewer | issue (untrusted), PR diff, repo checked out at PR head (includes ARCHITECTURE.md) | spec, design, test report, any agent conversation | assignment independence rule, and so it judges the change against the user's words, not our reading of them |
| Fix (round 2) | reviewer findings (list of {file, line, problem, category}) + original spec/design | the reviewer's reasoning text | the findings are actionable; the prose is not needed |

## Consequences
- + Every hand-off is a file in the run's artifacts, so anyone can follow a run (assignment Part 3).
- + Checks are possible because the hand-offs are JSON with a schema.
- − The Test agent may lack context the implementer had (for example a quirk of a mock). Mitigated by giving it ARCHITECTURE.md §6 (testing conventions) and the diff.
- − The reviewer may flag something the spec intentionally scoped out. Accepted: the human sees both the spec (artifact) and the review.
