# ADR-005: Tools are in-process Python functions with allow-lists; only deterministic steps hold a GitHub token

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D5 (tools)

## Context
The agents need to read, search, edit and run tests. GitHub write actions (push, PR, comment) are dangerous if an injected issue can steer them. My design notes: leave out any agent ability to do dangerous repo operations such as deleting the repo or changing ownership. The GitHub MCP server exposes dozens of tools, including merge and delete-branch, and the `gh` CLI with a token can do anything the token allows.

## Options considered
1. GitHub MCP server for all agents. Rich, but broad by default; even with restricted toolsets the token sits in the agent's process.
2. A generic `bash` tool (mini-swe-agent style). Maximum ability, but it can read the API key, `curl` anywhere, and `git push`.
3. **A small fixed tool set in `tools.py`. No shell tool. The `gh` CLI is used only by non-LLM steps in jobs that hold a token.** ← chosen

## Decision
| Tool | Spec | Design | Implementer | Test | Reviewer |
|---|---|---|---|---|---|
| `list_dir`, `read_file`, `grep` | – | ✓ | ✓ | ✓ | ✓ |
| `write_file`, `replace_in_file` | – | – | ✓ design files + `backend/tests/**` | ✓ `backend/tests/**` only | – |
| `run_build` (= `npm run build`) | – | – | ✓ | – | – |
| `run_tests` (= `npm test`, optional file filter) | – | – | ✓ | ✓ | ✓ |
| `finish` | ✓ | ✓ | ✓ | ✓ | ✓ |

All paths are resolved and rejected if outside the repo root, or inside `.git/`, `.github/`, `.autose/` or `node_modules/`, or (for writes) not on the allow-list. Commands are fixed strings, never model input. Child processes get a scrubbed environment (no `OPENROUTER_API_KEY`, `GITHUB_TOKEN`, `GH_TOKEN`, `ACTIONS_*`) and a 300 s timeout. `actions/checkout` uses `persist-credentials: false` in agent jobs, so `.git/config` holds no token.

Permissions per job: `gate` issues: write; `build`/`fix` contents: read; `release` contents: write + pull-requests: write + issues: write; `ci` contents: read; `review` contents: read + pull-requests: write (used only by the posting step after the agent step has ended).

## Consequences
- + Even a fully hijacked agent can only edit allow-listed files in a throw-away checkout. Its diff is still checked, reviewed, and needs a human to merge.
- − The agents cannot install packages or run arbitrary diagnostics. Acceptable for this repo, whose tests need only `npm test`.
- − More code to maintain than plugging in the GitHub MCP server.
