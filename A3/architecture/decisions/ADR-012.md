# ADR-012: Draft the PR with the output of the artifacts that it generated even if the later stages failed, so that we have some material for the run

- **Date:** 2026-11-24
- **Status:** Accepted (draft: rewrite in your own words). Extends [ADR-004](ADR-004.md) (the branch and PR carry state across runs); does not change [ADR-008](ADR-008.md) or [ADR-010](ADR-010.md).
- **Decision area:** D9 (safety and failures)

## Context
Until now a run that did not reach `ready` opened no PR. It left a stop comment on the issue (status and a one-line reason) and the stage artifacts in the Actions run, which must be downloaded and expire after 30 days.

The first real runs showed that this is not enough:
- Issue F2 (#7) failed at the design stage three times in a row (runs `45386362524`, `45387518256`, and one more). Each time the only visible result was one line, for example `design agent: unparsable replies: no JSON object found in reply`. Finding the real cause (Gemini spending the output limit on hidden thinking, then attempting native function calls) needed downloading `gitcore-build` and reading `transcript_design.jsonl` by hand.
- For the experiment, a failed run gave nothing to measure. The hidden tests need a PR head, so "stopped at testing with most of the fix done" and "stopped at the spec" looked the same in `results.csv`.
- A maintainer looking at the issue cannot see what GitCore understood (spec), planned (design) or wrote (partial diff) without opening the Actions UI.

Constraints from earlier decisions: only a human merges (ADR-010); the PR diff must contain only code and tests, never artifacts (ADR-004); the reviewer costs money and only makes sense on a change that passed GitCore's own checks (ADR-008).

## Options considered
1. **Keep the stop comment only.** Simplest and nothing extra on GitHub, but failed runs stay opaque and unmeasurable.
2. **Commit the artifacts (spec.md, design.md, transcripts) to the branch and open a normal PR.** Everything visible, but it pollutes the diff (rejected in ADR-004) and the PR looks merge-ready.
3. **Open a normal (ready) PR labelled `autose:failed`.** Visible, but it can be merged by mistake, and it would trigger the reviewer on code that already failed.
4. **Open a *draft* PR with whatever code exists (or an empty commit if the run stopped before implementation), put the spec, design and failure details in the PR body, and skip the reviewer.** ← chosen

## Decision
- When a first run ends with status `failed` or `budget_hit`, the release stage still pushes `autose/issue-<n>` and opens the PR **as a draft**:
  - If an implementation or test attempt produced a diff, the latest `diff.patch` is committed (the partial work).
  - If the run stopped at spec or design, the commit is empty (`--allow-empty`), so the PR changes no files.
- The title starts with `[draft, stopped at <stage>]`, the PR gets the `autose:failed` label, and the body begins with a banner: the stage it stopped at, the stop reason, the planned files from the design, and the last check failure. The spec's acceptance criteria and the design approach follow as in a normal PR.
- The stop comment on the issue links to the draft PR. The run summary shows `PR #N (draft)`.
- CI still runs on the draft (it shows how far the partial code got). **The reviewer is skipped** for drafts.
- Not drafted: `needs_clarification` (the questions belong on the issue, and the V1 experiment expects no PR) and a failed fix round (the round-1 PR stays as it was; the failure reason is commented on it).
- A later run on the same issue reuses the PR: if it succeeds, the PR is marked ready for review and `autose:failed` is removed.
- `GITCORE_DRAFT_ON_FAILURE=false` restores the old behaviour.

## Consequences
- + Every run that gets past stage 1 leaves something to inspect on GitHub, without downloading artifacts.
- + Hidden tests can run on a failed run's partial code, so `results.csv` shows how close a failed run came (`s5_release = draft`).
- + The diff still contains only code and tests (ADR-004 holds); the details are in the PR body.
- + A draft cannot be merged until a human deliberately marks it ready, so "a human merges" (ADR-010) is not weakened.
- − More PRs on the fork, some of them empty (a spec/design failure changes no files).
- − CI minutes are spent on code that already failed GitCore's checks.
- − Runs before this change opened no PR on failure. When the report compares failed runs, it must say which runs came before and after this ADR.
