# ADR-010: Triggers are the `autose` label or a `/autose` comment from a collaborator; one run per issue at a time

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D10 (triggers)

## Context
The assignment sketch uses `issues: labeled` and `issue_comment: created`. Any GitHub user can comment on a public repo, but only users with triage access or above can add labels. Two triggers in quick succession (label + comment, or two comments) must not produce two PRs for the same issue.

## Options considered
1. Any `/autose` comment starts a run. Easy to abuse: a stranger could spend the API budget.
2. Labels only. Safe, but no way to re-run a review from the PR page.
3. **Label `autose` or a `/autose` comment, with the gate job checking the sender's repository permission; `workflow_dispatch` for experiments; a concurrency group per issue that queues rather than cancels.** ← chosen

## Decision
- `issues: [labeled]` → continues only if `label.name == 'autose'`.
- `issue_comment: [created]` → continues only if the body starts with `/autose`. On an issue: the full pipeline. On a PR: `/autose review` runs one extra review on the current head (refused once two rounds are used).
- `workflow_dispatch` with `issue_number` and `variant` inputs, so experiment runs are repeatable and linkable.
- The gate calls `gh api repos/{owner}/{repo}/collaborators/{sender}/permission` and continues only for `admin`, `maintain` or `write`. Anyone else gets a comment and the run stops before any secret-using job starts.
- `concurrency: gitcore-<issue number>` with `cancel-in-progress: false`: a second trigger waits, then finds the branch and PR in place (ADR-004).
- Comments from bots are ignored, so the workflow's own comments cannot re-trigger it.

## Consequences
- + Outsiders cannot spend the budget; maintainers can trigger from the issue or the PR.
- + Duplicate triggers produce one PR, updated in place.
- − A queued second run repeats work if the first already succeeded. The gate skips issues whose PR already has `autose:approved` unless the comment says `/autose force`.
