# ADR-002: Control flow is a LangGraph state machine with code-owned routing, split across Actions jobs at permission boundaries

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D2 (control flow)

## Context
The stages are fixed, but there are loops (tests fail → implement again; reviewer disagrees → design or implementation again) and each loop needs a hard limit. A GitHub Actions job has one permission set, and the agent code must not run in a job that can push (ADR-005, ADR-009). An LLM planner could pick the next stage, but its decision would not be reproducible, and a planner that "decides the tests are fine" defeats the checks.

## Options considered
1. **LLM planner/orchestrator** that chooses the next stage. Flexible, but non-deterministic, hard to bound, and it can skip checks.
2. **One big job, fixed linear script.** Simple, but one token for everything and no clean place for loops.
3. **Separate workflows that trigger each other** (for example reviewer comment → new run). Events created with `GITHUB_TOKEN` do not start new workflow runs, so the chain would silently stop.
4. **State machine (LangGraph `StateGraph`) inside a job for stages 1–4; separate jobs chained with `needs:` for gate → build → release → ci → review → fix → release → ci → review.** ← chosen

## Decision
Inside the `build` job, `graph.py` defines nodes `spec → design → implement → test`. Each node runs its agent and then its check; conditional edges call routers that are pure Python reading the check results and counters in the state. Across jobs, the order is fixed in YAML with `needs:` and `if:` conditions. The second review round is a separate set of jobs (`fix`, `release_2`, `ci_2`, `review_2`), so "max 2 rounds" is enforced by the workflow structure itself, not by a counter an agent could be confused about.

**Who decides to go back:** always code. Test failures go back to Implementation within the attempt budget, then to Design once. Reviewer results route by the `category` field of the reviewer's JSON (`approach` → Design, `code`/`tests` → Implementation).

## Consequences
- + Every loop is bounded and visible in the Actions graph. A reader can see from the job list how far a run got.
- + The LangGraph state is a plain dict serialised to `state.json`, so the `fix` job can re-enter the graph at any node (ADR-004).
- − Some YAML duplication for the second round. Accepted for readability; a matrix cannot express "only if the previous review requested changes".
- − Routing by `category` trusts the reviewer's classification. A wrong label costs one round, not correctness, because every route ends in the same checks.
