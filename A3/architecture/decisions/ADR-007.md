# ADR-007: Stage checks are deterministic code; the only LLM judge is the reviewer, and code makes the final pass/fail call

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D7 (checks)

## Context
Each stage must pass a check before hand-over. If the agent that did the work also decides whether it passed, it will usually say yes. Tests and static checks are cheap and reproducible, but "all acceptance criteria are testable" and "the plan names files and functions" are partly judgement calls.

## Options considered
1. LLM judge per stage. Flexible, but costs a call per stage, can be argued with, and is not reproducible.
2. Agent self-report (`finish(status="ok")`). Free and worthless as a check.
3. **Code checks per stage, made possible by structured artifacts. An LLM judge only at Review, where judgement is the point, and even there the verdict is parsed and routed by code.** ← chosen

## Decision
| Stage | Check in `checks.py` |
|---|---|
| 1 Requirements | `spec.json` parses; ≥ 1 AC; each AC has `given`, `when`, `then`, `expected` (an exact value: status code, string, number, state) and `verify_by` (function or endpoint); no word from the A1 ambiguity lexicon (fast, easy, secure, robust, etc., …) in `then`/`expected`; no `PENDING`; `testable` true; `safety_flag` false |
| 2 Design | every `files[].path` exists unless `new: true`; every `functions[].name` is found in its file unless `new: true`; every AC id is covered by a change and by a planned test; all paths under `backend/` |
| 3 Implementation | `npm run build` exit 0; `git diff` not empty; changed paths ⊆ allowed set |
| 4 Testing | `npm test` exit 0; for each AC id at least one test name contains `AC-<k>` and passes; the number of `it(`/`test(` calls in pre-existing test files did not drop; no new `.skip`/`.only` |
| 5 Release | `gh pr view` state OPEN; the `ci` job (reusable `ci.yml`) concluded `success` |
| 6 Review | reviewer JSON parses; verdict ∈ {approve, request_changes}; an approval has evidence from at least one tool call; otherwise the verdict counts as `request_changes` |

The final decision on *merge* belongs to a human. The pass/fail decision for each stage belongs to the code above, which writes its result and reasons into the stage artifact.

## Consequences
- + Checks are reproducible: the same artifacts give the same result.
- + The spec check enforces the A1 skill's testability rules mechanically.
- − Code checks are shallow: a test named `AC-1` can pass without really testing AC-1. The independent reviewer and the hidden tests measure exactly that gap.
- − The ambiguity lexicon can reject a fine AC ("returns all rows" when "all" is precise). The Spec agent gets the rejected words back and one retry.
