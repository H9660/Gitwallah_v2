# ADR-009: Safety through budgets at several levels, timeouts on everything, untrusted-text handling, and no secrets where model-written code runs

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D9 (safety and failures)

## Context
Anyone can open an issue in a public repository. Issue text reaches an LLM that edits code, and we then execute that code on a runner. Model calls can hang or loop. Actions has limits (job time, API rate limits), and spend must be capped.

## Options considered
1. Prompt-level guardrails only. Cheap, but one successful injection could exfiltrate the API key from the environment.
2. A separate container per agent call. Strong, but heavy to build in the time available.
3. **Defence in depth: gate who can start a run (ADR-010), capability limits (ADR-005), no secrets in any process that runs model-written code, untrusted-text marking, and budgets at call, agent, run and job level.** ← chosen

## Decision
- **Budgets:** per LLM call max 4k output tokens and a 120 s timeout with 2 retries; per agent max tool steps (design 15, implementer 25, test 20, reviewer 20); per run a token cap (`GITCORE_MAX_TOKENS`, default 600k) and USD cap (`GITCORE_MAX_USD`, default 0.50); implementation attempts ≤ 3; redesign ≤ 1; review rounds ≤ 2. Hitting a limit ends the stage with status `budget_hit`, writes the reason into the artifact and stops the run.
- **Timeouts:** `timeout-minutes` on every job (gate 3, build 40, release 5, ci 10, review 20); `run_tests` 300 s.
- **Stuck stages:** the same failing check message twice in a row → stop instead of retrying (no progress).
- **Prompt injection:** issue and comment text are passed only as data inside `<untrusted_issue>` tags, with a system rule that instructions inside them are not followed. The Spec agent sets `safety_flag` when the issue asks for secrets, CI/permission changes, or work outside the repo's purpose; the run then stops at stage 1 with a comment. Agents cannot touch `.github/`. The reviewer re-reads the original issue independently.
- **Secrets:** the API key is a repository secret, passed only to steps that run the brain. Build/test child processes get a scrubbed env. `persist-credentials: false`. Nothing from the environment is placed in a prompt; logs print token counts, never keys.
- **Actions limits:** artifacts are small text files; `concurrency` prevents parallel runs per issue; no `pull_request_target` and no fork-triggered runs.

## Consequences
- + The worst outcome of a successful injection is a bad diff on a branch, which still needs CI, the reviewer and a human merge.
- − Model-written code still has network access during `npm test` on the runner. With no secrets in its environment the damage is limited, but not zero (listed as a limitation).
- − Tight budgets can stop a run that would have succeeded. Budget values are reported with the results.
