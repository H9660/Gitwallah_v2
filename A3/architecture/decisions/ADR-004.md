# ADR-004: State lives in state.json + workflow artifacts within a run; the branch, PR and labels carry state across runs

- **Date:** 2026-11-21
- **Status:** Accepted
- **Decision area:** D4 (state)

## Context
Jobs run on fresh runners, so nothing on disk survives between jobs. Stage outputs must be inspectable after the run. Runs can be restarted ("Re-run failed jobs"), re-triggered by a second `/autose` comment, or cancelled midway.

## Options considered
1. Commit artifacts to the PR branch. Visible, but they pollute the diff the reviewer sees and the human merges.
2. PR/issue comments as the state store. Visible, but parsing comments back is fragile, and comments can be edited by others (injection).
3. Actions cache. Not meant for correctness, and it can be evicted.
4. **`state.json` (graph state: stage, counters, check results, token use) + stage artifacts passed between jobs with `actions/upload-artifact` / `download-artifact`. Across runs, the only durable state is the branch `autose/issue-<n>`, its PR, and labels (`autose:running`, `autose:approved`, …).** ← chosen

## Decision
Each job downloads the previous job's `gitcore-*` artifact, runs, and uploads a new artifact with a job-specific name (`gitcore-build`, `gitcore-review-1`, …), so earlier versions are kept. `state.json` records `completed` stages with their check results; a node whose stage is already complete with a passing check is skipped, so "Re-run failed jobs" resumes instead of starting over. A fresh trigger on the same issue starts from stage 1: the branch is force-updated (`--force-with-lease`) and the existing PR is edited, not duplicated (`gh pr list --head autose/issue-<n>`). Artifacts are kept 30 days. The run record (tokens, cost, duration per stage) is part of `state.json` and feeds `results/results.csv`.

## Consequences
- + Anyone following a run sees every artifact in the Actions UI; the PR diff contains only code and tests.
- + Re-running a failed job is cheap: stages that passed are not repeated.
- − Cross-run history depends on artifacts that expire after 30 days. `results/runs.md` stores the links and the CSV stores the numbers, so the evidence survives.
- − Two simultaneous runs on one issue could fight over the branch. Prevented by the concurrency group (ADR-010).
