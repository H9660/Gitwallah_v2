# ADR-011: Call the Gemini API directly; keep the reviewer on a different model tier; another vendor stays optional per role

- **Date:** 2026-11-24
- **Status:** Accepted (draft: rewrite in your own words). Supersedes the provider and reviewer-model defaults of [ADR-006](ADR-006.md).
- **Decision area:** D6 (models)

## Context
ADR-006 routed every model call through OpenRouter, with a Gemini Flash builder and a reviewer from another vendor (DeepSeek). The first real run (`<FILL: Actions run link>`) stopped in stage 1 with HTTP 402. The prepaid OpenRouter balance could not cover one call's `max_tokens` reservation of 4,096 output tokens. The run itself behaved as designed: the spec stage failed, the reason went into the stop comment, and nothing was pushed. The run also showed two weaknesses in the harness:
- A non-retryable 402 was retried three times.
- Cost is only known when the provider reports it, and OpenRouter does, but a direct API does not.

I already have a Gemini API key with its own billing and quota.

## Options considered
1. **Keep OpenRouter and add credits.** Keeps the cross-vendor reviewer from ADR-006, but adds a second bill and a prepaid balance to watch during the experiments.
2. **Gemini API for the builders, OpenRouter for the reviewer only.** Keeps vendor diversity, but still needs OpenRouter credits.
3. **Gemini API for every role. The reviewer runs on a different Gemini tier (Pro instead of Flash). Any role can be moved to another provider with `GITCORE_BRAIN_<ROLE>`.** ← chosen

## Decision
- `brain.py` gets a `gemini` provider. It uses Google's OpenAI-compatible endpoint, so the same client code serves every provider. `BRAIN` defaults to `gemini`.
- Provider and model are chosen **per role**: `BRAIN_<ROLE>` falls back to `BRAIN`, and `MODEL_<ROLE>` falls back to `MODEL_BUILDER`. The reviewer defaults to `MODEL_REVIEWER` (a Pro model).
- The Gemini API reports token counts but not cost. Cost is computed from `GITCORE_PRICE_IN` / `GITCORE_PRICE_OUT` (USD per million tokens), with optional `_REVIEW` overrides, so the per-run USD cap from ADR-009 still works. Thinking tokens that appear only in `total_tokens` are counted as billed output.
- `reasoning_effort` defaults to `low`, so thinking tokens do not use up the `max_tokens` an agent needs for its JSON answer.
- HTTP errors other than 408/409/429/5xx (for example 400, 401, 402, 404) now fail immediately instead of being retried.

## Consequences
- + One key, one bill, quota managed in Google Cloud. No prepaid balance can stall a run halfway through the experiments.
- + Vendor diversity is still one variable away (`GITCORE_BRAIN_REVIEW=llm`, `MODEL_REVIEWER=<other vendor slug>`), so E1 can still test it.
- − **The default reviewer now shares the builders' model family.** This weakens one of ADR-008's independence measures. The remaining measures (separate job, limited context, adversarial prompt, evidence-required approval) are unchanged. Experiment E1 should report which reviewer model was used, and if possible include one cross-vendor reviewer variant.
- − Reported cost is an estimate from configured prices, not the provider's bill. Check it against the Google Cloud billing page after the experiments.
- − Gemini model codes differ from OpenRouter slugs (`gemini-2.5-flash`, not `google/gemini-2.5-flash`). The README records the codes actually used.
